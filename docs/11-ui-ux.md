# 11｜Web CAD UI/UX 信息架构与设计规范

## 11.1 产品视觉原则

- 专业而克制：中性底色、清晰的层次、低噪声工具栏、避免大量装饰性渐变。
- 可确认性：操作状态、单位、约束、几何失败、当前文档版本始终可见。
- 保持直接操纵：实体选择、相机导航、尺寸编辑、拖拽均有预测性和取消机制。
- 键鼠优先：CAD 主工作台面向桌面；触屏初期支持浏览不宣称完整编辑。

## 11.3 导航和编辑状态机

状态：`idle`, `select-plane`, `sketch-create`, `sketch-constrain`, `feature-edit`, `preview`, `rebuild`, `commit`, `error`。

- Escape：中断当前未提交工具/选择，但不删除已提交内容；连续 Esc 可清空选择。
- Enter：确认当前有效输入；当几何仍在计算时，不可误提交旧 preview。
- Ctrl/Cmd+Z：撤销当前编辑会话中最近的有效命令，不要求几何计算成功后才能关闭错误对话框。
- Space / 中键 / 滚轮：交互规范需可配置并为用户提供提示。
- 工具按钮根据当前状态禁用并展示原因，不能默默没有响应。

## 11.4 用户可见的工程反馈

| 反馈 | UI 位置 | 表现 |
| --- | --- | --- |
| 当前单位/捕捉模式 | 状态栏 | mm、Grid Snap、Object Snap |
| 草图状态 | 左侧特征树 + 状态栏 | Under-/Fully-/Over-constrained |
| 几何预览 | 3D 视口 | 半透明，不等同已提交 |
| 计算失败 | Feature Tree + 右侧诊断 | 显示失败特征、错误码、恢复动作 |
| AI 修改 | Agent Review Drawer | 命令差异、受影响特征、几何证据、审批按钮 |
| 文件转换 | Job Drawer | 格式、警告、进度、文件哈希 |

## 11.5 模型商店信息卡

每张卡显示：可读标题、分类、作者、最新 release、支持格式、可编辑等级、preview thumbnail 和授权标签。不要在卡片上同时叠加太多 badge；重要标签只有一个主要状态，其余置于详情。

## 11.6 响应式设计

- ≥1280px：左侧树 + 中央 viewport + 右侧属性 3 栏。
- 768–1279px：右侧属性抽屉，左侧树可折叠。
- <768px：只读模型浏览为主，复杂编辑操作给出桌面提示。

## 11.7 可访问性与国际化

- 中文/英文 UI 文案通过 i18n 字典，不拼接翻译片段；数字与单位格式按 locale 展示，保存仍为统一内部单位。
- 键盘焦点清晰、图标有 accessible label、工具有 tooltip 与文字菜单。
- 重要错误不能只用红/绿色区分；约束变化提供文字提示。
- 3D 视口需要提供相关信息的文本替代（尺寸、所选对象名称、错误），因为纯 3D 场景不可直接依赖屏幕阅读器访问。

## 11.8 设计交付物

P1 Figma/设计稿（可选）和可运行组件的视觉一致性测试；P2 工具状态机单测与 E2E：画草图→设尺寸→拉伸→修改尺寸→保存→重开。
