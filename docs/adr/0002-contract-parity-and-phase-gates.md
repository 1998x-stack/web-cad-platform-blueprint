# ADR-0002｜冻结跨运行时文档语义，并以 G0/G1/G2 管理 P0–P2

- **Status:** Proposed; requires implementation PR + runtime evidence before Accepted
- **Date:** 2026-11-17
- **Review scope:** P0–P2 next milestone, does **not** supersede ADR-0001 native OCCT reference use

## Context

Repo's command engine accepts unsorted feature DAGs while Python builds features in their array order. TS/JSON Schema enum and Python/native also disagree on supported types or evidence shapes. Parameters in the document currently do not drive B-Rep geometry. P1 release membership is mutable and P2/P3 export dependencies are mixed.

## Proposed decision

1. Publish one canonical versioned JSON Schema family and generated TS/Python DTOs; validate golden accepted/rejected fixtures in each runtime.
2. Features form a DAG with deterministic topological evaluation, independent of array order; use an explicit root/outputBodyId. Document and runtime both reject invalid cycles and refs.
3. Scalar properties may be literal or typed parameter references; versioned unit/precision policy, no `eval`.
4. Browser WebAssembly runs in a dedicated single-thread Worker first. `GeometryEvidence` is generated by kernel validation, not rendered mesh. Native OCCT remains independent oracle.
5. G0 for browser geometry + STEP + constraints, G1 for Model Library security and reuse, G2 for editable Sketch→Exact B-Rep→Save→STEP loop; P1 data UI may proceed in parallel with P0 geometry Spike, but public completion claims cannot skip gates.
6. P1 copies and downloads fixed release refs; P2 implements Open in Studio. P2 may use P0's narrow STEP export and does not depend on the full P3 job/format pipeline.

## Alternatives considered

- Accept feature array order as mandatory: simpler native implementation but contradicts current JS behavior and complicates independent UI feature ordering; could still be chosen if benchmarked and documented, but would require synchronized rejection rules and migrations.
- Mesh-first UI without B-Rep worker: rejected as a CAD MVP because it cannot prove exact STEP semantics.
- Make P1 depend on P2: rejected as it unnecessarily delays usable model discovery/preview.
- Immediate custom C++ OCCT build/multithreaded WASM: deferred until a proven single-thread package cannot meet needed operation coverage/performance.

## Consequences and acceptance

Schema upgrade work must precede geometry Worker; previous v1 examples may require versioned migrations and fixture updates. No implementation claim until the corresponding PR shows Node/Python/Browser acceptance and numerical evidence.
